Two Ways to Use AI

Vibe coding vs agentic coding

Vibe coding

  • "Just make it work"
  • Accept whatever the AI produces
  • Don't read the code
  • No conventions, no checks
  • Hope for the best

Fine for a throwaway prototype. Dangerous for a paper.

Agentic coding

  • Constrain the agent with rules
  • Verify every output
  • Numbered scripts, robust SEs, no absolute paths
  • A second agent audits the first
  • Paper trail writes itself

Reproducible, verifiable, publishable.

This workshop is about the right column. Not prompt tricks — reliable habits.

Part 1

How Agents Work

Key Distinction

This isn't the ChatGPT you know

Chatbot

  • Tells you what to do
  • One response at a time
  • You copy-paste everything
  • No memory between turns

Agent

  • Does it for you
  • Multi-step workflows
  • .R files appear on disk
  • Sees errors, fixes them

How It Works

The agent loop

Agents observe each result and decide what to do next.

  1. Observe — read your files, check what exists
  2. Plan — decide which script to write next
  3. Execute — write the code and run it
  4. Check — did it work? Parse errors, read output
  5. Repeat — fix what broke, move to the next step

This is why they recover from errors. They see what went wrong and try again — just like you would.

Your Job

Decompose → Constrain → Verify

The agent handles execution. You handle direction.

  • Decompose — break a vague research task into numbered, concrete steps
  • Constrain — specify packages (estimatr), SE type (HC2), file format (RDS), plot style (theme_tufte)
  • Verify — check every output before moving on

The prompt is a contract. The more specific you are, the fewer surprises. Let me show you what that looks like.

Part 2

Inside the Code

Walking through what the agent actually produces

First: Teach the Agent Your Rules

WARP.md — persistent project context

Create this file in your project root. The agent reads it at the start of every session, so you only set conventions once.

What to include

  • Project description and status
  • Data sources and locations
  • R version and key packages
  • Known issues or limitations

Rules you enforce

  • here::here() for all paths
  • Robust SEs by default
  • theme_tufte() for all plots
  • Sequential script numbering
  • LaTeX macros for all stats

These rules become the builder skill we'll see later. For now, notice: the agent follows whatever conventions you write down.

Walkthrough — 01_clean_data.R

# ==============================================================================
# 01_clean_data.R
# Purpose: Load and clean raw survey data
# Input:   data/raw/survey_2024.csv
# Output:  data/processed/survey_clean.rds
# ==============================================================================

library(here)
library(tidyverse)

raw <- read_csv(here("data", "raw", "processed.csv"),
                 skip = 2)  # skip Qualtrics metadata rows

cat("Raw rows:", nrow(raw), "\n")

clean <- raw |>
  mutate(
    pop_index = rowMeans(across(pop_1.n:pop_6.n), na.rm = TRUE),
    age       = as.numeric(age),
    country   = factor(country)
  ) |>
  filter(!is.na(pop_index))  # explicit, not na.omit()

cat("Clean rows:", nrow(clean), "| Dropped:",
    nrow(raw) - nrow(clean), "\n")

saveRDS(clean, here("data", "processed", "populism_clean.rds"))

Walkthrough — 03_analysis.R

# ==============================================================================
# 03_analysis.R
# Purpose: Estimate main models, export coefficients as LaTeX macros
# Input:   data/processed/survey_clean.rds
# Output:  output/statistics.tex, output/tables/main_models.tex
# ==============================================================================

library(here)
library(estimatr)
library(modelsummary)

df <- readRDS(here("data", "processed", "populism_clean.rds"))

# Main model — robust (HC2) standard errors
m1 <- lm_robust(pop_index ~ age + ed_postsec +
                            globalization_country.n +
                            rwa.n + loss_1.n,
               data = df, se_type = "HC2")

# Export ALL statistics as LaTeX macros — never hardcode
sink(here("output", "statistics.tex"))
cat(sprintf("\\newcommand{\\nObs}{%s}\n",
           format(nobs(m1), big.mark = ",")))
cat(sprintf("\\newcommand{\\mainCoef}{%.3f}\n", coef(m1)["rwa.n"]))
cat(sprintf("\\newcommand{\\mainSE}{%.3f}\n",   m1$std.error["rwa.n"]))
cat(sprintf("\\newcommand{\\mainP}{%.3f}\n",    m1$p.value["rwa.n"]))
cat(sprintf("\\newcommand{\\rSquared}{%.3f}\n",  summary(m1)$r.squared))
sink()

Walkthrough — 04_figures.R

# ==============================================================================
# 04_figures.R
# Purpose: Publication-ready coefficient plot
# Input:   data/processed/survey_clean.rds
# Output:  figures/coef_plot.pdf, figures/coef_plot.png
# ==============================================================================

library(here)
library(estimatr)
library(ggplot2)
library(ggthemes)
library(broom)

df <- readRDS(here("data", "processed", "populism_clean.rds"))

m1 <- lm_robust(pop_index ~ age + ed_postsec +
                            globalization_country.n +
                            rwa.n + loss_1.n,
               data = df, se_type = "HC2")

p <- tidy(m1) |>
  filter(term != "(Intercept)") |>
  ggplot(aes(x = estimate, y = reorder(term, estimate))) +
  geom_vline(xintercept = 0, linetype = "dashed", color = "grey60") +
  geom_pointrange(aes(xmin = conf.low, xmax = conf.high), size = 0.8) +
  labs(x = "Coefficient estimate (95% CI)", y = NULL) +
  theme_tufte(base_size = 14)

ggsave(here("figures", "coef_plot.pdf"),
       plot = p, device = cairo_pdf, width = 6.5, height = 4.5)
ggsave(here("figures", "coef_plot.png"),
       plot = p, width = 6.5, height = 4.5, dpi = 300)

Part 3

Where Agents Fail

Caution

What agents get wrong in R

These are real mistakes I've seen agents make. They present every one with full confidence.

  • na.omit() without telling you — silently drops hundreds of rows, changes your N
  • Default lm() standard errors — should be lm_robust() with HC2 or clustered
  • Absolute paths — /Users/you/... breaks on every other machine
  • Hardcoded numbers — types "p < 0.001" in LaTeX when the real p is 0.047
  • Missing set.seed() — bootstrap CIs shift on every run
  • Wrong cluster level — clusters by respondent when it should cluster by household

The scary part: these look right at a glance. You need a systematic way to catch them. That's where Part 4 comes in.

statistics.tex — The LaTeX Macro Pattern

Never hardcode a number

What the agent writes:

\newcommand{\nObs}{72,814}
\newcommand{\mainCoef}{0.342}
\newcommand{\mainSE}{0.012}
\newcommand{\mainP}{0.001}
\newcommand{\rSquared}{0.241}
\newcommand{\nCountries}{4}

What you write in your paper:

Our sample includes \nObs{} respondents
across \nCountries{} countries. The main
effect of RWA on populist attitudes is
$\beta = \mainCoef{}$ (SE $= \mainSE{}$,
$p = \mainP{}$). The model explains
\rSquared{} of the variance.

Re-run the analysis → statistics.tex updates → paper updates automatically. Zero manual transcription errors.

Part 4 — The Core Idea

Two agents are better than one

One agent builds. A second agent tries to break what the first built.

The builder is confident. The reviewer is adversarial.
Together, they catch what either would miss alone.

The Pattern

Build → Review → Fix → Review

1. Build

Invoke /builder-agent
Produces .R scripts, figures, stats.tex

→

2. Review

Switch model, invoke /reviewer-agent
Runs checks, Python verification

→

3. Fix

Builder addresses critical issues
Re-runs pipeline

→

4. Re-review

Reviewer confirms fixes
Produces final report

Strategy

Different models, different blind spots

/builder and /reviewer can run on different models from different providers.

Why cross-provider?

  • Each model has its own failure modes
  • Claude may miss what GPT catches (and vice versa)
  • Disagreement between models is a signal to investigate
  • Avoids correlated errors from the same training data

Example combinations

Reviewer: GPT-4o

Walkthrough — audit_analysis.py (written by the reviewer agent in Python)

"""Audit R analysis pipeline — run by reviewer agent."""
import subprocess, re
from pathlib import Path
import pandas as pd
import statsmodels.api as sm

# 1. Run every .R script and capture errors
for script in sorted(Path(".").glob("*.R")):
    result = subprocess.run(["Rscript", "--vanilla", str(script)],
                             capture_output=True, text=True)
    status = "PASS" if result.returncode == 0 else "FAIL"
    print(f"{status}: {script.name}")

# 2. Cross-check N against statistics.tex
df = pd.read_csv("data/processed/populism_clean.csv")
with open("output/statistics.tex") as f:
    tex = f.read()
reported_n = int(re.search(r"\\nObs\}\{([\d,]+)\}", tex).group(1).replace(",", ""))
assert len(df) == reported_n, \
    f"ROW COUNT MISMATCH: data has {len(df)}, stats.tex reports {reported_n}"

# 3. Re-estimate key coefficient with statsmodels
X = sm.add_constant(df[["age", "ed_postsec", "rwa_n"]])
y = df["pop_index"]
model = sm.OLS(y, X).fit(cov_type="HC2")

r_coef = float(re.search(r"\\mainCoef\}\{([\d.]+)\}", tex).group(1))
py_coef = model.params["rwa_n"]
assert abs(r_coef - py_coef) < 0.01, \
    f"COEFFICIENT MISMATCH: R={r_coef}, Python={py_coef:.4f}"

print("All checks passed.")

What the Reviewer Catches

Real examples of silent failures

🔴 Dropped 312 observations

Builder used na.omit() silently. Reviewer's Python check: pd.read_csv().shape[0] ≠ reported N in statistics.tex

🔴 Wrong cluster level

Clustered by respondent_id but data has multiple respondents per household. Reviewer checked with groupby('household_id')['respondent_id'].nunique()

🔴 Hardcoded p-value

Builder wrote p < 0.001 in LaTeX but actual p = 0.047. Reviewer's statsmodels re-estimation caught the discrepancy.

🟡 Missing set.seed()

Results changed on re-run. Reviewer ran the pipeline twice and diffed outputs — bootstrap CIs shifted.

Implications

Equilibrium

The new balance

Costs collapse ↓

  • Data cleaning — parsing, merging, recoding
  • Analysis — models, robustness checks, figures
  • Documentation — READMEs, session logs, LaTeX
  • Verification — adversarial review, stress tests

Value rises ↑

  • Ideas — original questions, creative design
  • Taste — knowing what's worth doing
  • Fieldwork — being there, in person
  • Judgment — knowing when the agent is wrong

12:00

Summary

Three things

  1. Constrain the agent. Conventions in WARP.md. Numbered scripts. No absolute paths. Robust SEs.
  2. Review adversarially. A second agent — on a different model — catches what the first misses. Use Python to verify R.
  3. Document by default. LaTeX macros, session logs, git commits. The paper trail writes itself.

How to Install and Invoke in Warp

Three steps

1. Copy the skill files into your project:

my-project/
├── .warp/skills/
│   ├── builder-agent/
│   │   └── SKILL.md
│   └── reviewer-agent/
│       └── SKILL.md
├── data/
└── WARP.md

Also works: .agents/skills/, .claude/skills/, .cursor/skills/
Global (all projects): ~/.warp/skills/

2. Type / in Warp’s input bar to invoke:

/builder-agent Analyze the populism
  data at data/raw/processed.csv...

Warp auto-discovers skills and shows them in the / menu. You can also just describe your task — the agent finds the right skill.

3. Click the model selector, switch model, invoke reviewer:

# Model selector → GPT-4o
/reviewer-agent Audit everything
  the builder just produced.

Warp reads the SKILL.md automatically when you invoke it. The agent follows the full procedure, conventions, and checklist — you never repeat instructions.
